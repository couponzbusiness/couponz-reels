# 대본까지의 제작 측 사용법

1. 사용자는 공식 혜택 링크 또는 혜택 지정, 예정 사용일을 전달합니다. 앱 전용인 경우 필요한 경로·조건 화면녹화를 받습니다. 본인 목소리와 필요한 배경영상은 후속 제작 재료이며 이 단계에서는 없어도 대본 준비를 진행합니다.
2. `intake`로 기존 자료 경로와 요청을 기록합니다. 자동 수집·OCR·ASR 결과는 생성되지 않습니다. 제작 담당자가 공식 조건을 직접 읽고 원문 위치·확인 시각·검토 수준을 기록해야 합니다.
3. 제작 측이 주장표를 만듭니다. 예시 계약은 `fixtures/A.json`이며 입력마다 `synthetic: false`와 실제 근거를 사용합니다. 가상 근거를 복사해 실제 행사로 바꾸지 않습니다. 현재 대본 엔진 통화는 KRW만 지원합니다.
4. 소재의 중심 질문에 따라 `single`, `comparison`, `procedure`, `roundup`, `cart` 중 주 형식을 선택하고 `format_reason`을 적습니다. 질문·대상·기간 강조는 도입 변형이며 별도 여섯 번째 형식이 아닙니다. 앱 화면이 있다는 이유만으로 절차형, 상품이 여러 개라는 이유만으로 합산형을 선택하지 않습니다.
5. `validate`의 `issues`를 확인합니다. 조건·기간·세금·필수비용·동일 기준·주장값이 불명확하거나 충돌하면 `hold`입니다. 보류 상태의 대본은 각 문장이 `provisional`이며 현행 혜택 안내에 사용하지 않습니다. 실제 발급·결제 완료와 예상 금액은 별도 상태입니다.
6. `draft`로 한국어 대본과 문장별 역할·주장 경로를 생성합니다. 출력은 시작 양식입니다. 길이·템포·화면 전환·효과·자막 스타일은 설정하지 않습니다. CTA는 입력에 있을 때만 후보로 넣고, 사실 보류 상태에서는 생략합니다. 현재 CTA는 `{"action": "check_conditions"}` 또는 `{"action": "save_for_reference"}` 두 가지 비사실적 권고 문구만 지원합니다. 자유문장 CTA는 미검증 혜택 주장이 끼어들 수 있어 보류합니다. 문장 자연스러움과 중요한 조건의 의미는 사람이 검토합니다.
7. 사용자 피드백을 반영할 때 새 출력 경로를 사용합니다. 파일을 덮어쓰지 않지만 이것을 전체 의존성 고정·승인 버전 관리·복원 검증이라고 부르지 않습니다. 가격·조건·대본이 바뀌면 관련 사실과 문장을 다시 검토합니다.

## 주장·근거 계약

`offers`의 대상·채널·기간·최소금액·상한·제외·중복·세금·필수비용·통화를 기록합니다. 값이 없으면 `null`이며 0이 아닙니다. 0은 원문에서 제한이나 비용이 없다고 확인한 경우에만 씁니다. 날짜는 예정 사용일 기준으로 유효해야 합니다.

각 주장 경로(예: `offers.0.price`)의 `provenance`에는 해당 `evidence.id`를 연결합니다. 근거에는 종류, 확인 시각(시간대 포함), 원문 위치 `locator`, 검토 여부와 `assertions`의 실제 확인값을 기록합니다. 입력값과 근거값의 충돌·누락을 검사합니다. `reviewed: true`는 제작 담당자의 기록이며 프로그램이 원본을 열었다는 증거가 아닙니다. 임의로 true를 입력하는 것만으로 혜택이 검증되지 않습니다. 자유문장 의미 분석·출처 진위 검증은 아직 없습니다.

비교에는 상품 종류·모델·수량·구성·자격·통화·세금 기준과 필수비용이 필요합니다. 비교 기준이 다르면 절약 계산을 보류합니다. 세금 별도라면 실제 비교 세액 `tax_amount`가 확인되어야 총액을 비교합니다. `declared_saving`이 산식과 다르면 차단합니다. 합산에는 상품별 단가·수량, 즉시쿠폰·최소금액·필수비용, 별도 보상 ID·종류·조건을 기록합니다. 세금 별도일 때는 `cart.tax_amount`도 필요합니다. `declared_payable`이 미래 보상을 즉시 차감한 값이면 차단합니다. 여러 거래 합산은 현재 지원하지 않아 보류합니다. 보상 `condition`은 완전한 한국어 문장으로 작성합니다.

`claimed_state: paid`는 완전한 지급 완료 증거의 `scope: paid_receipt`가 해당 가격 주장에 연결되어야 합니다. 포스터·예상 화면·부분 영수증·청구 잔액만으로 승격하지 않습니다. `issued`도 해당 상태의 완전한 근거가 필요합니다. 생성 대본은 현재 보수적으로 예상 금액과 별도 확인 문구를 사용합니다.

## 개인정보와 공개 저장소

실제 사용자 자료·분석 원문·영상·녹음·개인정보·비밀키는 저장소 밖에 둡니다. `.gitignore`는 실수 방지 보조책이며 공개 가능성 검토를 대신하지 않습니다. 현재 코드에는 외부 업로드·push·공유변경·API 호출이 없습니다. synthetic JSON만 공개 가능한 시험재료로 준비했습니다.
